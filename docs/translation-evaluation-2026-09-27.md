# 翻译系统样本评估报告（2026-09-27）

## 1. 结论

本轮已经验证系统 1 主体接入系统 2 的 PaddleOCR，并使用 Qwen3.8-Flash 完成真实样本翻译。当前方案对普通 DOCX 和原生文本 PDF 的正文翻译已具备可用性；对扫描 PDF 能恢复主要文字和表格内容，但复杂旋转表格、双栏、图片、页眉页脚和视觉样式的版式还原仍不具备直接生产交付水平。

建议生产默认并发设为 6，测试环境可先设为 8；12 仅作为小文档压测上限，不建议在未完成接口限流和长文档稳定性验证前作为默认值。所有药品、疫苗、GMP 或质量体系文件仍须由业务人员复核后发布。

## 2. 测试范围与方法

- 翻译模型：Qwen3.8-Flash，OpenAI-compatible 接口。
- OCR：PaddleOCR 服务，由系统 2 的内部 OCR API 提供。
- 系统链路：PDF -> PaddleOCR -> DOCX 中间稿 -> 系统 1 翻译引擎 -> Qwen3.8-Flash -> DOCX。
- DOCX 质量样本：蛋白质含量检验标准操作规程中文原稿、英文参考稿。
- 扫描 PDF：87 页硅胶管验证文件，选取第 1、10、40、87 页作为不同版式代表页。
- 原生文本 PDF：73 页合规与持续改进材料，选取第 1、20、40、73 页作为代表页。
- 并发测试：同一页 OCR 中间稿，分别以 1、2、4、6、8、12 并发执行；每档 1 次预热、3 次正式运行。
- 版式评估：候选 DOCX 逐页渲染，与原稿和参考稿人工对照。

本轮不是对两个长 PDF 的全页翻译验收。代表页用于识别版式能力和链路问题；完整 87 页、73 页长文档仍需在测试服务器进行持续时间、限流、内存和失败恢复测试。

## 3. 内容与结构结果

### 3.1 普通 DOCX（SOP，中译英）

- 中文原稿与候选稿均为 95 个正文段落、9 个表格、5 个分节。
- 9 个表格的行列结构全部一致。
- 文档标识符保留 42/42，召回率和精确率均为 100%。
- 候选稿无中文残留。
- 数字匹配 353/359，召回率 98.33%，精确率 100%。缺少的 6 个数字实际被模型拼写成英文单词，并非内容段落丢失。针对该问题已增加数字保真检查和严格纠错提示，后续新任务会要求数字继续使用阿拉伯数字。
- 候选稿 19 页，人工英文参考稿 21 页。正文、标题、表格和页眉整体可读，无裁切；修订历史表比参考稿更紧凑。
- 可见的小问题包括部分样式片段连接处缺空格，以及个别窄列表格换行较密。适合进入人工复核，不应直接替代受控翻译审签。

综合评价：内容良好，结构保持强，版式良好但仍需排版复核。

### 3.2 扫描 PDF（代表页，中译英）

- 4 个代表页共识别 37 个内容块、16,913 个字符，包含 text、table、image 三类。
- 端到端运行：OCR 26.336 秒，翻译 201.001 秒，总计 227.337 秒；并发 8；245 个翻译片段；最终错误数 0。
- 正文、主要表格及化学/工艺内容可以进入后续翻译，旋转表格也能被识别为表格结构。
- 品牌 Logo、页脚装饰数字和部分图片内文字存在 OCR 噪声。
- 4 页原稿生成 8 页译文。旋转密集表格被拆成多页窄列表格，横向布局和旋转方向未保留；正文表格可读，但原稿页眉页脚、图片和视觉风格未被忠实还原。

综合评价：内容提取可用，装饰性内容识别一般，复杂扫描版式还原较差。现阶段适合作为“可编辑翻译初稿”，不适合作为“原版式复刻成品”。

### 3.3 原生文本 PDF（代表页，英译中）

- 4 个代表页共识别 33 个内容块、6,308 个字符。
- 端到端运行：OCR 24.770 秒，翻译 88.040 秒，总计 112.810 秒；并发 8；33 个翻译片段；最终错误数 0。
- CQA、CPP、CMA、FMEA、FTA、OOS、BSC、UDAF、CCS 等术语和编号得到保留。
- 输出 4 页，中文正文清晰、无裁切，问题与回答顺序正确。
- 原稿双栏、颜色、图形和品牌设计被简化为单栏纯文本。OCR 断行会把跨段句子切碎，影响上下文完整性。

综合评价：文字识别与翻译质量良好，版式忠实度一般。对有可靠文本层的 PDF，应增加“文本层直读”快速路径，仅在扫描页或低质量页启用 OCR。

### 3.4 其他输入问题

- 硅胶管英文参考 DOCX 的 ZIP 中央目录损坏，自动比较工具无法可靠读取；Word 可尝试修复打开，但该文件不宜作为自动评测基准。这是输入文件缺陷。
- EU GMP 中英对照 DOCX 已含双语配对。当前翻译引擎没有“双语对照识别/只处理指定语言栏”模式，直接翻译会造成英文保留、中文再译，产生重复或错位。本轮未把它当作普通单语文件整篇翻译。

## 5. 本轮已实施的改进

- Qwen OpenAI-compatible 地址适配，避免原生通义适配器与兼容接口混用。
- PaddleOCR HTML 表格转换为真实 DOCX 表格，支持 rowspan/colspan 合并。
- 模型错误不再被静默计为成功，任务会统计并上报错误。
- 相同文本的并发翻译共享同一个进行中请求，降低重复调用。
- 增加可配置的片段外层重试，默认最多 2 次。
- 增加数字保真质检和严格纠错提示，要求阿拉伯数字、单位及标识符保持一致。
- URL 和邮箱从中文语言比例检查中排除，避免对必须原样保留的内容进行无效重试；真正未翻译的英文句子仍会被拦截。
- 增加真实链路评测入口、并发基准 CSV、文档结构/数字/标识符比较工具及回归测试。

## 7. 上线前优先事项

1. 增加 PDF 文本层检测和混合页路由：文本页直接解析，扫描页调用 PaddleOCR。
2. 对旋转表格、双栏阅读顺序、图片锚点和页眉页脚增加版式模型或原页面背景叠加策略。
3. 增加双语对照文档模式，识别语言列/段落，只翻译指定一侧。
4. 在测试服务器对完整 87 页、73 页文件做并发 6/8 的长文档测试，并记录失败重试、吞吐、内存和 API 限流。
5. 增加术语库、受控词表、句段重组和人工审校工作流；法规/质量文件必须保留审签责任。
6. 对 OCR 生成的 DOCX 补齐标准节属性，避免第三方渲染器兼容性问题。
