# 翻译质量优化验收记录（2026-09-28）

## 结论

本轮样本驱动优化达到“可编辑翻译初稿”验收线：系统 1 仍是业务主体；文本型 PDF 优先走本地 PyMuPDF，扫描型 PDF 回退 PaddleOCR，随后统一交给系统 1 的 Qwen3.8-Flash 翻译链路。受测输出的数字、文档编号、段落/表格/节结构及目标语言残留质量门均通过，48 个输出页面已逐页检查，未发现截断、重叠、表格越界或缺字。

该结论不等于药品/GMP 文件正式批准。术语、法规语义和最终版式仍须业务人员复核后才能发布。

## 本轮修复

- 数字、单位、日期、百分比、文件编号和化学位次在模型调用前使用确定性占位符保护；恢复后进行次数级而非集合级校验。
- 严格格式模式按完整段落翻译，避免逐 run 翻译导致语序、空格和上下文破坏。
- 缺失术语、数字或占位符进入一次严格纠正；仍不满足时返回失败，不再把原文回退冒充成功。
- 修复化学名称 `2,4,2',4'` 被拆成两个占位符的问题。
- 修复目标中文检测：一处中文字符不再使整句英文被误判为“已是中文”。
- 中英交替双语文档保守检测并原样旁路，避免重复翻译。
- 文本型 PDF 增加原生文本快速路径；扫描件保留 PaddleOCR。
- PDF 转 DOCX 按源页尺寸建立节，宽页/宽表使用横向节，表格使用有效 `tblGrid`、重复表头和受控字号。
- LLM 日志不再写入完整提示词、原文或译文，只记录长度和耗时。
- 质量工具支持次数级数字/编号、中文章节号、英文/中文数量词和样品管序数等价，以及中文目标中的整句英文残留检测。

## 失败驱动的迭代证据

1. 首次扫描 PDF 翻译失败：化学位次被拆分后模型丢失占位符。新增回归测试并合并为单个受保护 token 后，端到端重跑通过。
2. OCR DOCX 缺少 `w:tblGrid`，Python-DOCX 无法稳定读取。新增失败测试、生成有效表格网格，并让评估器兼容历史无网格文件。
3. 扫描结果出现 `第二章 → Chapter 2`，最初被误报为新增数字。质量工具增加中英文编号语义等价，仍保持次数严格相等。
4. 英译中逐页目检发现英文句末带一个汉字时被误判为中文而跳过。修复语言比例判断，真实单段 Qwen 验证得到“根据测试产品的来源，制备测试样品管。”，随后整文重跑通过。
5. 英文数量词 `Two`、中文“两个”和 `first → 第一` 最初产生数字精度误报。新增定向回归并按受限样品数量/序数上下文归一，未放宽一般数字门。

## 版式检查

- 中文 SOP → 英文：20 页；逐页可读，页眉、表格、修订历史和附件未截断。
- 英文 SOP → 中文：16 页；逐页可读；修复后的第 7 页无英文源文回显。
- 原生文本 PDF：4 个源页生成 5 个可编辑输出页；内容可因译文长度自然扩页，无截断或重叠。
- PaddleOCR PDF：4 个源页生成 7 个可编辑输出页；旋转宽表转换为横向 Word 表格，续表可读，无越界。
- 样本 PDF 原图与输出逐页对照；附件中的 `AAA` 等字符来自源扫描页，不是本轮 OCR 新增。

由于本机未安装 LibreOffice，按文档技能的降级路径使用 Microsoft Word 只读导出 PDF，再使用 Poppler 渲染 PNG；所有中间文件均位于 D 盘测试目录或 `D:\Temp`。
